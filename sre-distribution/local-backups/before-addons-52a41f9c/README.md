## 三个 JAR 如何选

所有 JAR 的 Mod ID 都是 `cobblemon`，版本都是 `1.8.4+1.21.1`。
**同一个实例的 mods 里只能放其中一个，不要将三个 JAR 一起安装，也不要同时保留原 Cobblemon JAR。**

| 文件后缀 | 用途 | 内容 |
| --- | --- | --- |
| `client-full-split.jar` | 客户端 | 全部原玩法、代码、数据、运行库；资源外置，语言仅简中/繁中/美式英语；保留约 100 KiB 启动兜底资源 |
| `server-full-split.jar` | 需要完整宝可梦玩法的专用服务器 | 保留全部原代码、玩法数据与运行库，删除客户端美术、语言和内置资源包，只有服务端入口 |
| `server-shell.jar` | 不启用宝可梦玩法的列车专用服务器 | 独立 Java 注册占位模组，只保留静态注册身份、方块状态及 Fabric 同步；没有原 Cobblemon 玩法代码、数据包、Kotlin/Graal/Mongo/Showdown |

客户端完整包仍保留集成服务器所需代码，可用于原有完整玩法；“拆分资源”不等于删掉客户端功能。
完整服务端保留客户端类文件以避免公共 API 的延迟类加载依赖被破坏，但没有客户端入口或资源，也不会在专用服务器运行客户端代码。

## 资源包

将 `resourcepacks/` 内 ZIP 放进客户端的 `resourcepacks` 目录，并在资源包设置中启用 `Cobblemon-1.8.4-resources.zip`。
主包恢复完整模型、贴图、动画、声音和粒子；它不含语言，三种语言由客户端 JAR 提供。
代码和玩法数据来自本次精确提交的源码构建；美术、语言和可选包沿用此前核对的 1.8.4 原发行资源。
两者全部 19,226 个资源路径完全一致；沿用原发行资源避免将更大的源码素材重新引入，也保持你现有资源内容不变。
清单中的 `assetReference` 记录原始完整 JAR 的 SHA-256，打包阶段逐文件核对所有资源。
四个可选包保持原本语义，按需启用并放在主包之上：Adorn 兼容、暴鲤龙跳跃外观、地区外观、独特闪光外观。
服务器无需加载这些 ZIP；客户端不启用主包时只剩启动/占位资源，不是完整外观。
资源外置不保证启用相同资源时降低客户端运行内存。

## 空壳的重要边界

已按用户确认的“极简注册表空壳”实现，不保留附属模组 API 或原宝可梦存档支持。
它不会生成、捕获、战斗、骑乘、繁殖或存储宝可梦，不注册相关玩法命令、配方、世界生成、玩家队伍和业务网络同步。
注册表中的自定义物品是无功能占位物；实体工厂禁止生成，方块不提供原来的交互或方块实体逻辑。

**不要用空壳版打开包含 Cobblemon 内容的已有存档；必须使用新世界或确认不含相关内容的列车世界，并先备份。**
客户端、玩家背包、附加数据包也不应携带需要原宝可梦业务编解码器的数据。
特别是创造模式的 Cobblemon 复杂组件物品并不属于支持范围；空壳会拒绝这些业务数据，不能把“能正常入服”解释为所有创造物品操作都兼容。

空壳服不要运行 Mega Showdown 等依赖 Cobblemon 内部实现的宝可梦附属或服务端注入补丁；它们的 mod ID 检测通过，不代表所需类/API 存在。
完整客户端本身可连接空壳；其他附属自己的握手或客户端逻辑需要另行测试。

## 精简策略

完整两个版本保留每个 class、玩法 data、Showdown 脚本、Mixin、access widener 和内嵌运行库；不冒险删除 Graal/ICU/Kotlin/Mongo 来伪装“完整功能”。
客户端删除非保留语言，主体美术资源外置，所有 ZIP 使用最大 DEFLATE 压缩；完整服务器额外完全移除客户端资源。
空壳是独立实现，不加载原来的重量级运行库，但 493 个方块的 34,143 个状态仍必须保留，以匹配原客户端协议，不能无限压成只有一个模组 ID 的空文件。

## 构建与校验

构建环境为 Java 21、Gradle 8.14.3；上游 Architectury Loom 1.11.458、Kotlin 2.2.20。
实际完整构建在 H 盘的同提交隔离副本执行，避免源码 G 盘/输出 H 盘导致 Kotlin 增量缓存相对路径错误，并避免耗尽 C、G 盘。
源码 `settings.gradle.kts` 仅新增默认关闭的 `trainFabricOnly` 参数；只影响本次是否配置 NeoForge，不修改任何原游戏实现。

完整构建使用：

```bash
GRADLE_USER_HOME='H:/gradle-home' \
GRADLE_RO_DEP_CACHE='C:/Users/canyuesama/.gradle/caches' \
./gradlew :fabric:remapJar -PtrainFabricOnly=true -Dfabric.loom.ci=true \
  -Dorg.gradle.jvmargs=-Xmx4G -Pkotlin.incremental=false \
  -Pkotlin.compiler.execution.strategy=in-process --max-workers=2 --console=plain
```

`fabric.loom.ci` 只跳过 IDE 用的依赖源码下载，不删游戏依赖；缺少必要二进制时仍正常报错。
`sre-distribution/` 保存空壳 Java 源码、精确快照、打包和隔离验证脚本；脚本中工具链路径是本机配置，异机复现需配置对应 Minecraft 映射、Fabric API 与 TinyRemapper 路径。
完整构建的原 JAR 在打包后逐文件核对，两个完整版本每个 class 和所有保留数据/库保持构建产物原字节；客户端资源逐文件匹配上述原发行资源；所有 ZIP 校验 CRC。
`distribution-manifest.json` 与 `SHA256SUMS.txt` 记录产物大小、哈希、精确保留语言与兜底清单。

实际验证结果见随包 `verification/`，以对应 JAR 和资源包 SHA-256 为准。
已完成的原客户端连接空壳测试覆盖 26 类、1,652 个注册项及 34,143 个方块状态一致，入服后运行 120 tick，加载 985 个模型解析项。
未验证整套列车整合包、全部附属、所有创造物品操作或长时间联机；不对这些范围作兼容承诺。

许可证：保留 Cobblemon MPL-2.0；原始作者版权与资源许可仍适用。源码已保存在指定仓库，发行包不代表官方发行版。
